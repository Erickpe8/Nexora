# Convenciones de Código — Nexora

## Idioma
TODO el proyecto debe estar en español:
- Variables
- Funciones
- Interfaces y Types
- Componentes
- Carpetas
- Comentarios
- Archivos

## Nomenclatura
- Componentes en PascalCase
- Variables y funciones en camelCase
- Un archivo por componente
- Uso obligatorio de interfaces/types

## Estilo de código
- Código limpio y minimalista
- Uso moderado de azúcar sintáctico
- Evitar lógica excesiva dentro de componentes
- Separación clara de responsabilidades
- Simplicidad antes que sobreingeniería

## Comentarios
- Solo cuando aporten valor real
- Explicar lógica compleja
- Evitar comentarios innecesarios o redundantes

## Estructura de carpetas
```
src/
├── components/
├── screens/
├── services/
├── hooks/
├── navigation/
├── types/
├── utils/
└── styles/
```

## Reglas de arquitectura
- Mantener componentes reutilizables
- Separar lógica de negocio de la UI
- Mantener servicios API desacoplados
- Evitar componentes gigantes
- Mantener organización simple y mantenible
